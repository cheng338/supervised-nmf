Ubuntu benchmark instructions

Extract the sNMF benchmark ZIP on the Ubuntu PC and activate its existing
Python environment. The sNMF source is included; do not install it
from PyPI or replace it with an installed package.

The comparison includes the real 8-core/16-thread PC, this Ubuntu PC, and a
projected 16-core/32-thread PC with 96 GB RAM. The projection is calculated
from PC1's qualified full results and requires no additional run.

Wait for substantial competing jobs to finish. From the extracted folder run:

  sh RUN_SWEEP.sh --label PC2

Compatibility checks run automatically. The sweep starts with 1 worker x 1 thread,
then tests 2 workers x 1 thread and 1 worker x 2 threads. It repeats that pair for
larger thread counts up to the available CPU threads. It uses ordinary OS
scheduling. Each fit uses CD with absolute cutoff 2.0.

To test only the initial three cases:

  python3 sweep.py --label PC2-basic --counts 1,2

Training size is chosen automatically from available RAM at the maximum worker
count, with OS/temporary-array headroom. That per-fit size stays fixed throughout
the sweep. Fewer simultaneous workers use less total RAM.

Retain the entire new folder under results/, including compatibility.json,
sweep.json, sweep-summary.md, and every case subfolder. If a check fails, retain
the saved report and terminal output. If no fit completes inside a timing window,
retain the result so both PCs can be rerun with a longer common window.

The target's numerical-library versions were checked on Windows/Python 3.12;
the automatic checks validate this actual Ubuntu/Python 3.10 environment. No
existing environment should be changed. README.md has the short instructions;
PROTOCOL.md and VALIDATION.md retain technical and validation details.
